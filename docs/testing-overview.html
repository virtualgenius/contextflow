Gaps worth knowing about

Pipeline

  • Tests run in CI but not in the git hooks. A push with a failing test still leaves the laptop. The suite takes about five seconds, so adding npm run test:run to the pre-push hook is a one-line change.
  • Worker integration test skips without a live worker. Two tests need a server on port 8787 and now skip rather than fail when none answers. Run npm run dev:local to exercise them.
  • No browser-level tests. Real WebSocket sync, offline and reconnect, file import, and canvas drag are only verified by hand. The Playwright plan in docs/TESTING_STRATEGY.md was never implemented.

Acceptance coverage

  • The canvas has no component test. Pan, zoom, fit-to-map, drag to reposition, multi-select and group drag, drag-to-connect, and the N and arrow-key shortcuts all live in CanvasArea.tsx, which no test renders. This is the most-used surface in the product and the one where a React Flow upgrade would break silently.
  • Temporal evolution UI is untested. The timeline slider, keyframe editor, and keyframe manager have no tests. Only the interpolation helpers do, so a broken slider would still pass.
  • Value Stream and Strategic views are tested at the store, not on screen. The user and user-need nodes, the three connection edge types, and every view overlay (distillation regions, evolution bands, stage boundaries, axis labels) have no component tests.
  • Four dialogs are untested: project create, project delete, group create, and import conflict. The actions behind them are covered, so the gap is wiring, not logic.
  • Two features have no test at all: the light and dark theme toggle, and the live CodeCohesion repository statistics fetch.
  • Most component tests check wiring, not outcomes. The dominant shape is "calls onX when clicked" against a mocked store. The handful of true outer-loop tests (undo buttons driven by real Yjs, Context Map preserving value-stream data, two-browser sync, add-related-context) are the strongest tests in the repo and the pattern worth extending.
